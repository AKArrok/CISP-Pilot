26次登录、身份核验、退出和原Cookie重放401均通过；2次错误密码/未知账号401通过。服务原密码计算峰值并行2，实际PID与Popen祖先关系核对，RSS峰值约386.9MiB。健康探针均200；原服务日志无ERROR/Traceback；服务与启动器均停止。默认库前后SHA保持。

首个错误密码请求单独处于Redis未连接状态，约3.21秒；末次未知账号为暖缓存约1.26秒。两者不作未知账号与错误密码恒定时间比较，因为缓存条件不同。主阶段密码计算约1.23—1.25秒，8用户排队最长3.76秒，支持两路密码任务队列为本次登录尾延迟主要构成，不能单靠小样本百分位外推生产容量。没有为降低延迟而削弱scrypt或增加内存并行任务。

原失败保留：第一轮Locust读取UTF8 TOML时GBK失败；r2采了启动器PID且探针未读完正文导致连接异常；r3修正真实PID与连接，资源数据有效，但旧Cookie未被重放，撤销证据不足；r4补足旧Cookie重放及负例。不能把前几轮弱证据计为通过。

本次改进的是测试方法与诊断证据，应用认证代码未修改。会话复用已由项目实现，业务负载应继续使用预认证会话隔离登录成本。真实模型并发、跨实例Redis、生产数据库和长期稳定性仍需单独冻结验证。

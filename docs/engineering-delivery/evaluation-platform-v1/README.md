## 目标

先交付服务 CISP 开发者的 AI 质量测评中台：在本地浏览器中完成“查看冻结题集 → 导入已有评测批次 → 查看逐题证据 → 比较两个版本 → 记录复核结论 → 导出报告”。以现有真实失败案例验证可用性。数据中台及学生考试测评留作后续阶段。

第一版支持历史结果导入及不调用模型的离线检查。付费在线评测执行、默认业务库迁移和部署不包含在本计划中；后续接入前分别核对授权、预算及外发范围。

## 当前依据与边界

- 当前路线图为 EVALUATION_LOOP.md 顶部；实施时认证接续入口为 auth-limit-20261109，质量历史为 evaluation-window3-20261107；既有语义失败及审阅校准不足必须保留。
- 现有 scripts 下包含评测、审计、比较及报告脚本，优先复用其产物与判据；先检查实际 schema，不重写评分逻辑。
- 沿用现有 Python Web 服务及 static 页面方式；中台元数据使用独立 SQLite 路径，不修改 data/cisp_qa.db。
- 工作区存在用户已有改动，实施前逐项核对，只提交本任务文件。
- 原始私有证据只在获准本机范围内读取，不进入公开提交或默认导出。普通登录不自动获得全部实验资料的访问权限。

## 页面与数据范围

1. 总览：批次、失败数、缺证据项、费用已知/未知状态；每项显示统计分母和来源。
2. 数据集：题目、版本摘要、开发/回归/未见集角色、评分标准及来源信息。
3. 批次：配置、代码与数据摘要、运行状态、原始产物关联；未知信息明确为空。
4. 逐题详情：问题、回答、实际可用的检索与引用证据、分项判定、失败原因；缺失字段不推断补齐。
5. 版本比较：仅对可比较的共同题目统计修复与退化，另列新增/缺失题及配置变化。
6. 复核与报告：追加复核意见和理由，保留原判；导出 Markdown/JSON，默认排除私有原文。

共享实体至少包含 dataset/version、run、case_result、review_event、artifact。导入记录绑定内容哈希和来源位置；原始产物保持只读。具体表结构在核对产物后确定。

## 第一版完成条件

- 可从浏览器导入或选择获准批次、筛选失败、查看逐题证据，并导出可追溯报告。
- 两个批次可比较时，能够正确显示修复、退化、未变以及不可比较项；原历史评分和失败记录不被覆盖。
- 复核记录可追溯到账号、时间、依据及目标答案版本；AI 审阅与人工复核分别标记。
- 至少一组现有历史失败在页面中完整呈现；页面统计与冻结原始记录逐项核对一致。
- 无付费模型调用，默认业务库哈希不变，访问隔离及核心浏览器流程验证通过。

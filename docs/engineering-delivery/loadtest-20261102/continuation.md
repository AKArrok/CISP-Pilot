# Locust 本机隔离并发试跑

日期：2026-11-02。目标是实际使用专业负载工具验证项目的本机并发链路，不宣称生产容量。

工具：Locust 2.47.0，Python 3.11.15。目标为 Git 提交 72a2699 的隔离导出副本，合成 SQLite 与合成题库；真实 HTTP、身份验证、SSE、线程与刷题持久化链路。聊天路由和回答节点替换为确定性本地 fixture，关闭 dense、rerank 和真实模型访问，Redis 不可达时按项目机制降级为单进程内存。未使用私有课程材料或默认库写入。用户等待 1—2 秒，聊天和刷题任务权重 3:1，逐级 1、4、8 用户，每级 20 秒，启动速率每秒 2 用户。方案和场景分别见 plan.json 和 locustfile.py。

CSV 为 Locust 结束时的最近统计快照，不保证已包含停止瞬间所有仍在执行的请求；例如 8 用户档控制台最终显示 chat 18 次，而 stats.csv 快照为 16 次。以下统一使用 CSV 快照，可重复核对；每级在统计快照中的所有请求失败数均为 0。

统计检查 SSE 正常结束且不含 error；刷题检查问题 ID 与答题返回字段。登录、注册和线程创建分别计数，不把它们的延迟当作聊天延迟。注册/登录是每个用户的准备步骤，在较短 20 秒窗口占据较多时间；因此有效稳定负载时间更短，8 用户测试样本少，百分位不稳定；登录 P95 表明值得进一步定位，但不能仅凭本次运行判定根因或容量。输出的 RPS 包括爬坡与准备期，不作为极限吞吐量。

原始统计、失败和异常文件分别为 stage-{1,4,8}_stats.csv、_stats_history.csv、_failures.csv、_exceptions.csv。每组 failures 与 exceptions 为空表。运行前后默认 data/cisp_qa.db SHA-256 均为 3d6d78663b9378d8791f1692afcdd702c9476866d5458c3492f307766e9d5b62；测试服务已停止。本轮外部模型调用 0，费用 0。

Locust 在此 Windows 环境导出的 CSV 使用重复回车换行；原始字节保存在本机 raw-original，提交的 CSV 只规范化了换行，字段和数值未改变。

该实验未衡量真实模型延迟、真实资料检索、多个服务实例、网络延迟、长时间稳定性或资源使用，不能推断生产环境的 P95、QPS 和可承载人数。下一步若需量化登录瓶颈，应在隔离环境提前准备账号、分别测试认证和业务链路、延长稳定期并记录 CPU/内存；如需真实模型结果需另行冻结发送内容与调用预算。

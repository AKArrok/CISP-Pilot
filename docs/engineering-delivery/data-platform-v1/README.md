## 目标与验收

把真实失败关联到知识资产版本、来源/切片候选和改进复测记录。零新模型调用，不写默认库、不修改默认索引，不将测试答案导入知识库。本轮沿用既有相关代码推送授权。

1. 参考成熟案例并冻结来源 → 验证：固定提交及文件blob摘要可追踪。
2. 建立隔离库中的不可变资产快照与质量检查 → 验证：重复导入、版本变化、缺原文、ID冲突/父块/索引错配、业务库保护。
3. 连接测评失败与切片血缘 → 验证：真实哈希绑定、截断片段与同名多匹配、缺失证据均分别标注，不能把当前库猜成历史库。
4. 失败分项分析、改进项及复测关联 → 验证：固定答案/题目/标准、追加历史、并发与幂等、不可比复测不能包装修复。
5. 页面与浏览器端到端、回归、文档和推送 → 核实精确提交CI、资产前后哈希。

## 成熟案例参考及项目取舍

固定提交、文件路径与blob SHA见[sources.json](sources.json)。阅读目标源码/协议和主许可证，不安装或运行第三方系统，不外发本机业务资料。以下为本项目设计取舍，并非兼容其协议或已接入产品。

- DataHub：阅读元数据模型说明、UpstreamLineage/Upstream模型。采用资产稳定身份、不可变版本、关系来源与匹配状态分离；本机用SQLite实现，不引入图数据库和搜索集群。
- OpenLineage：阅读RunEvent、DatasetVersion及DataQualityMetrics协议。采用数据版本、处理器身份、输入输出摘要和检查结果分开记录；当前仅采集文件现场，不伪造历史任务START/COMPLETE事件，不声称OpenLineage兼容。
- DVC：阅读stage序列化及dvcfile锁文件写入逻辑。采用输入/参数/输出摘要冻结；不新增DVC依赖或远程存储。

DataHub首次尝试metadata-model路径404，按其模型文档确认实际为metadata-models后读取；全仓递归树不适合连接器大小限制，改为精确文件读取。旧iterative/dvc返回迁移，公开搜索定位treeverse/dvc后读取并固定提交。没有把搜索摘要当作实现证据。

### 保留的失败与局限

- 精简`ac-8-new-03`核心结论正确，但引用定位写成`ac-8_gdn`，实际提供的是`ac-8`；旧引用标准直接判失败，未放宽标准。
- 两臂`scenario-01`把口头同意的形式问题推成资料规定的确定性禁止。基线后文自己承认资料未规定形式，候选进一步称书面批准要求；因此两臂均源支持不足，改进复测为unresolved。
- 默认`ca-8-new-01`额外说自动扫描是渗透的“起点或基础手段”，原文goes beyond未支持这个确定性层级关系；候选避免了该扩展。本轮只计一次观察，不声称稳定修复。
- 精简`ac-8-new-08`两次出处虽换行，却仍插在句中且后接正文；`ac-8-new-02/06/07`仍有题外扩展，`at-2-new-03`问两种却列五种。独立换行修复不等于完整末尾出处段或全面精简验收。候选不晋级默认；不通过重试挑一轮好答案覆盖失败。
- 多轮为两个会话各3轮的冻结AI开发检查：指代、切题、跨会话及SQL历史2/4/6条通过。真实改写调用已记入回执，不能把6轮当成6个独立无历史样本，更不能泛化为长对话无污染。

## 重复检索调查：现有折叠在起作用

[诊断](retrieval-diagnostic.json)使用实际HybridRetriever的BM25候选与父段折叠代码，无模型调用。101个公开物理块只有8份父正文，同一完整正文的变体共享parent_id。原40题最终Top2均有两个不同父证据、目标命中40/40；两个真实40题批次的预览与离线诊断均逐条一致40/40。

只在诊断中取消已有父段折叠，38/40题的前两名会重复。这个反事实证明已有去重机制在防止证据占位，不是线上缺少一个新去重功能。本机1077块的10条通用探针也未出现最终Top2重复；只保存计数和指纹，私有正文不公开。此前数据中台71个child_text重复告警与本次93个重复父正文变体的口径不同，二者都不直接证明模型最终看到了重复上下文。

本轮未发现当前40题“重复检索挤掉相关证据”的失败，因此释放0.10USD条件预留，不追加付费重复检索臂，不盲删切片。该结论不覆盖任意问题、其他dense/rerank配置或语义近重复，也不证明答案中的重复叙述由检索引起。

# 知识点标签开发集、Dense A/B 与外部验收

## 开发集

`tests/fixtures/profile_accuracy_dev.json` 是允许用于错误分析和参数选择的开发集。它从当前
题库中排除校准集、旧 holdout、人工题号覆盖、重复题和待复核题，再按
`sha256(dev-v1:question_id)` 稳定排序，每个知识域取 5 题，共 50 题。

开发集不能作为泛化成绩。它的价值是区分知识点缺失、知识域错分和标签器选错。

## Dense A/B

Dense 方案使用项目当前配置的真实 embedding 模型，为题目和知识点名称、同义词生成向量。
第二轮不再把题库原始知识域作为硬约束：先在十域中按每域 top-3 相似度聚合推断知识域，
并把原始知识域作为可调软先验；再在推断域内召回 top-5，执行证据约束。推断查询文本不包含
原始知识域，避免标签泄漏。向量使用项目现有磁盘缓存，重复网格评测不会重复请求相同文本。

在开发集补齐 9 个缺失概念/等价标签后，50 题结果：

| 方法 | 覆盖率 | 端到端准确率 | 有输出时准确率 |
|---|---:|---:|---:|
| 字符 TF-IDF | 70% | 48% | 68.57% |
| Dense + 原始域硬约束 | 82% | 52% | 63.41% |
| Dense v3 + 语义域推断 | 98% | 74% | 75.51% |

原始域标签相对审校域只有 66% 正确；纯语义域推断为 80%，加入 0.02 软先验后最高为 84%。
端到端最优参数则是 0.05 软先验、0.45 相似度阈值、0 margin。Dense v3 还把
候选集改为“dense top-5 与全目录强词面证据的并集”，避免正确选项明示某概念却在
top-5 候选阶段被丢弃。域指标和端到端指标的最优
参数不同，说明仍有明显的域内相邻概念混淆。

这些数字全部是允许查看预测、补目录和选参数的开发集结果，不是泛化准确率。知识目录已针对
该开发集达到 50/50 覆盖，因此 74% 很可能含有开发集适配收益；在双盲外部 holdout 完成前，
不得据此替换生产 TF-IDF 标签器，也不得宣称画像准确率达到 74%。旧 holdout 已经消费，只能
做回归检查，不能继续参与参数选择。

运行：

```bash
python tests/eval_profile_dev.py
```

结果写入 `data/profile_accuracy_dev_report.json`。

## 第二审校者盲审

以下命令生成不含第一版金标和模型预测的 100 题盲审包：

```bash
python scripts/create_blind_review_packet.py \
  --cases tests/fixtures/profile_accuracy_holdout.json \
  --output data/review_packets/profile_holdout_second_review.json
```

第二审校者必须独立填写 `reviewer_id`、`reviewed_at`、`reviewed_domain` 和
`acceptable_knowledge_points`。完成后运行：

```bash
python scripts/score_blind_review.py \
  --gold tests/fixtures/profile_accuracy_holdout.json \
  --review data/review_packets/profile_holdout_second_review.json \
  --output data/review_packets/profile_holdout_second_review_status.json
```

空白或未签署的审校包返回状态码 2，不得视为完成。Codex 不能冒充第二名人类审校者。

## 外部 holdout 硬门槛

`profile_accuracy_external_holdout.template.json` 规定最终验收材料。只有同时满足以下条件才会
执行模型评分：

- 至少 100 道不在当前题库中的外部题目；
- 记录来源 URL、取得时间以及许可或使用依据；
- 两名不同审校者均声明未查看模型预测；
- 每道题保留两人的独立标签和最终裁决标签；
- 两组标签至少 80% 有交集；
- 冻结 SHA-256 与题目、标签内容一致。

```bash
python tests/eval_profile_external_holdout.py --method dense
```

材料不完整时返回状态码 2 并写出 `blocked` 报告；完整但准确率不达标返回 1；只有完整且
覆盖率、准确率都达到 80% 才返回 0。当前尚无具备明确使用许可的外部 CISP 题源和第二名
审校者，因此最终外部验收仍处于 blocked，而不是 passed。双包互盲、裁决和内容去重的完整
执行命令见 `docs/12-外部holdout双人盲审执行.md`。

## 保守聚合当前开发集快照

2026-09-15 使用 `python scripts/build_taxonomy.py`（未启用 dense）和
`python scripts/evaluate_attribution.py --gold tests/fixtures/profile_accuracy_dev.json`
生成了 `data/attribution_report.json`。新报告不是把拒答当正确：在 50 道开发题中，
13 道进入 `confirmed/probable`，其中 13 道命中可接受知识点；37 道保持
`unverified`。因此本次快照的接受覆盖率为 **26%**，已接受输出的已知标签精度为
**100%（13/13）**，而不是宣称整体准确率 100%。

作为历史参照，旧单路字符 TF-IDF 报告是覆盖率 70%、全体题准确率 48%、有输出时
准确率 68.57%。这两个数字不能直接当作同一指标的前后提升：新口径明确拒绝不确定
候选，且本次 dense 后端不可用；它证明的是当前配置偏 precision-first，代价是覆盖率
明显下降。全题库快照为 `confirmed=12 / probable=302 / unverified=1046`；由于本次未启用 dense，
报告中的 dense 不可用率为 100%，外部 holdout 仍为 `optional_blocked`。阈值如需调整，只能在开发集上
做，并且必须重新生成该报告；不能用这组数字替代外部双盲验收。

## 保守聚合 Dense v3 快照

2026-09-17 已在项目当前配置的真实 embedding 后端上执行：

```bash
python scripts/build_taxonomy.py --with-dense
python scripts/evaluate_attribution.py \
  --results data/question_attributions.json \
  --gold tests/fixtures/profile_accuracy_dev.json \
  --output data/attribution_report_dense.json
```

v3 仍然是三路保守聚合，没有放宽接受阈值：在知识点专用检索文本中补入父级主题，
并在“不包括 / 不属于 / 错误的是 / 不需要”等否定题中，不再把正确选项误当成
目标概念的正向证据。同时将题目 embedding 改为批量请求，避免每题重写整个向量缓存。

50 题开发集的递进结果如下：

| 版本 | 已接受且正确 | 接受覆盖率 | confirmed | 候选误归因率 |
|---|---:|---:|---:|---:|
| 未启用 dense | 13/13 | 26% | 0 | — |
| dense 基线 | 17/17 | 34% | 13 | 34% |
| + 父级主题 | 18/18 | 36% | 14 | 26% |
| v3 + 否定题处理 | 19/19 | 38% | 15 | 26% |

最终 v3 的 50 题中，`confirmed=15 / probable=4 / unverified=31`。已接受输出的已知
标签精度是 100% (19/19)，但 probable 只有 4 个样本，报告正确标记为
`insufficient`；这组数据不支持“整体准确率 100%”或“已证明泛化”的结论。

全部 1360 题的状态为 `confirmed=237 / probable=179 / unverified=944`，接受覆盖率
30.59%，拒绝率 69.41%，三路分歧率 46.84%，dense 不可用率 0%。高分歧率说明
剩余样本仍然不适合通过降阈值强行接纳。外部 holdout 仍为 `optional_blocked`；在取得
合规外部题源和两名独立盲审者之前，该快照只是开发集适配结果。

## 2026-09-23 知识点与领域联合口径

复核评分实现时发现：旧 `observed_misattribution_rate` 在知识点金标存在时只比较知识点，
不会检查同时提供的审校领域。因此，“知识点选对、领域选错”会被旧指标算作正确。为保持旧报告
可追溯，该字段与原有 confirmed/probable precision 语义不变；新报告额外提供领域错配率、
候选领域准确率、联合错配率，以及 confirmed/probable 的领域准确率和联合精度。候选领域缺失
按错算；拒绝输出不进入候选条件指标分母，仍由覆盖率单独反映。没有可接受知识点且没有审校领域的
空标签行不计作已知金标；只有领域标签的样本仍可按领域评分。

在同一份 50 题开发金标和现有预测快照上复算，生成
`data/attribution_report_2026-09-23_domain-aware.json`：

| 指标 | 结果 | 解释 |
|---|---:|---|
| 旧知识点优先错配率 | 13/50（26%） | 保持旧字段，知识点金标存在时不检查领域 |
| 候选领域错配率 | 9/50（18%） | 仅有领域金标且有候选的题；领域缺失算错 |
| 候选领域准确率 | 41/50（82%） | 候选领域与审校领域一致 |
| 知识点或领域联合错配率 | 14/50（28%） | 两者任一错误；拒绝输出不计入此条件分母 |
| confirmed 知识点精度 | 15/15（100%） | 不等于完整归因准确率 |
| confirmed 领域准确率 / 联合精度 | 14/15（93.3%） | 显示旧 15/15 精度掩盖的一道领域错误 |
| probable 知识点/领域/联合精度 | 各 4/4（100%） | 每项样本数仅 4，仍标记 `insufficient` |

该报告只重评当前工作区已有预测，没有重新调用模型、重建 taxonomy 或消费 holdout；输入路径与 SHA-256
记录在报告 provenance 中。以上仍是开发集指标，不是独立泛化准确率；`external_holdout.status`
继续为 `optional_blocked`，双人盲审要求没有改变。

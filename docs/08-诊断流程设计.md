# 入门诊断与知识点画像

## 当前实现范围

诊断和普通刷题是两条路径。普通刷题仍使用 `/quiz/next`；诊断使用持久化会话，
不会因为刷新页面而换题：

```text
POST /diagnostic/start
    ↓
GET  /diagnostic/{session_id}/next
    ↓
POST /diagnostic/{session_id}/answer
    ↓（重复 next/answer，直到达到停止条件）
GET  /diagnostic/{session_id}/report
```

`selected_domains` 是用户自评的 1～4 个薄弱域。刻意限制数量，避免用户把“全量摸底”
误当成一次精细诊断；全量覆盖应拆成多次会话。它只作为先验，不直接写入
`weak=true`。诊断前 4 题优先覆盖用户选择的域，第 5 题插入未选择域作为校准，
之后按后验不确定性继续选择。默认 6～12 题，最多 20 题；焦点域每个至少获得
两条证据后才允许提前停止。

每次回答同时写入按 `thread_id` 隔离的 `learner_attempts`、`learner_review_cards`、
`learner_knowledge_states` 和 `diagnostic_events`。旧全局答题/复习数据无法可靠归属用户，
不会迁移进新画像。报告将结果分成：

- `self_report`：用户自述，只是先验；
- `diagnostic`：诊断题的直接证据；
- `insufficient`：样本不足，不强行下结论。
- `knowledge_points[*].provisional`：知识点标签尚未人工审校时，只作覆盖提示，不能当作确定性结论。

## 构建知识点候选

```bash
python scripts/build_taxonomy.py
python scripts/build_taxonomy.py --import-db
```

脚本只使用结构化课件标题和题干的可重复启发式规则，不调用 LLM。它生成：

- `data/knowledge_taxonomy.json`：知识域下的知识点候选，包含教材证据数、题目覆盖数；
- `data/question_knowledge_tags.json`：题目到知识点的多标签，含主标签和置信度。

当前目录包含 580 个知识点，其中 305 个 active、264 个 candidate、11 个 rejected；
题目标签 813 条。精细画像只使用可用的主知识点标签；没有标签的题仍保留为知识域证据，
不会伪造知识点结论。

知识点模型允许一题对应多个点，后续可继续增加：

- `prerequisite`：前置知识；
- `confused_with`：易混概念；
- `misconception`：错误认识；
- `bloom_level` / `difficulty`：认知层级和难度。

## API 示例

```json
POST /diagnostic/start
{
  "thread_id": "default",
  "selected_domains": ["信息安全支撑技术", "信息安全评估"],
  "self_report": {
    "goal": "冲刺",
    "exam_date": "2026-11-01",
    "daily_minutes": 45,
    "experience": "学过一遍但概念容易混淆",
    "domain_status": {
      "信息安全支撑技术": "学过但忘了",
      "信息安全评估": "做题不稳定"
    }
  },
  "max_questions": 12
}
```

答题时可带 `confidence: 0～3` 和 `reason`。它们不改变确定性判分，只用于区分
“答对但没把握”和“真正掌握”：比较确定/非常确定却答错会标记
`misconception_risk`，没把握/有点把握但答对会标记 `fragile_knowledge`。用户填写的
理由只作为后续追问证据，不直接改变 Beta 掌握度。报告页的一键
“进入针对性对话”会把域级证据交给现有 Tutor/RAG，并要求它先追问不超过 3 个澄清
问题，再给解释和练习顺序；诊断控制器本身不调用 LLM。

## 后续迭代边界

下一步不是新增知识域 Agent，而是审校候选树、补题目主/次知识点标签，并把选题
效用从“域级不确定性”下沉为“知识点覆盖 + 考试权重 + 前置影响 + 遗忘程度”。
教学仍由现有 Tutor/RAG 流程负责，诊断选择和判分保持确定性代码。
